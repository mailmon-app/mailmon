# NPM Publishing for Mailmon Packages

The Mailmon monorepo publishes multiple NPM packages, including:

- `@mailmon.dev/sdk`: The TypeScript SDK generated by Speakeasy in `sdks/typescript-new`.
- `@mailmon.dev/cli`: The Mailmon command-line interface.

We use Changesets for semantic versioning, changelog generation, and NPM publishing. GitHub Actions owns the release process.

## Publishing Workflow

### 1. Add a Changeset

When a pull request changes a publishable package, create a changeset:

```bash
pnpm changeset
```

Select the changed package, choose the SemVer bump, and write the release note. For SDK changes, select `@mailmon.dev/sdk`; the publishable workspace package is `sdks/typescript-new`.

### 2. Version Packages PR

After the change lands on `main`, `.github/workflows/release.yml` runs Changesets. If unpublished changesets exist, it creates or updates a `Version Packages` PR containing:

- Version bumps in package manifests.
- Consumed changeset removal.
- Changelog updates.

### 3. Publish to NPM

Merge the `Version Packages` PR when the release is ready. The release workflow then runs `pnpm release`, which:

1. Builds shared library packages.
2. Builds the checked-in Speakeasy SDK.
3. Builds the CLI.
4. Publishes packages with `changeset publish`.
5. Creates package tags such as `@mailmon.dev/sdk@0.2.8`.

Regenerate the SDK before merging release changes. The checked-in SDK source is what the release workflow builds and publishes.

## SDK Generation Workflow

Automated SDK regeneration outside publishing is handled by `.github/workflows/sdk_generation.yaml`.

That workflow runs the root Speakeasy monorepo target:

```yaml
target: mailmon-typescript
```

It writes SDK changes to `sdks/typescript-new` and opens a PR in `mode: pr`. The workflow requires:

- `SPEAKEASY_API_KEY`
- `GITHUB_TOKEN`

Use this workflow for routine SDK refreshes. Use the release workflow for publishing.

## Security and Authentication

NPM publishing uses Trusted Publishing through OpenID Connect. No long-lived `NPM_TOKEN` is required.

For each package (`@mailmon.dev/sdk` and `@mailmon.dev/cli`), an organization admin must configure NPM to trust this GitHub repository:

1. Log in to npmjs.com.
2. Open the package settings.
3. Add a Trusted Publisher.
4. Select GitHub Actions.
5. Configure:
   - Organization or user: `mailmon-app`
   - Repository: `mailmon`
   - Workflow filename: `release.yml`
   - Environment name: leave blank

## Local Configuration Highlights

- `.speakeasy/workflow.yaml`: Root Speakeasy monorepo workflow mapping `mailmon-api` to `sdks/typescript-new`.
- `sdks/typescript-new/.speakeasy/gen.yaml`: TypeScript SDK generation and package metadata.
- `scripts/generate-sdk-for-release.mjs`: Local/CI regeneration script that preserves Changesets versioning and changelog output when Speakeasy credentials are available.
- `sdks/typescript-new/package.json`: Publishable `@mailmon.dev/sdk` package.
- `sdks/typescript/package.json`: Legacy Fern SDK package, marked private and renamed so it is not published.
- `.changeset/config.json`: Configures public package publishing.

Do not manually publish from inside `sdks/typescript-new`. Use Changesets and the root release workflow so the CLI and SDK stay on the same release process.
